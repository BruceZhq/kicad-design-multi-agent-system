# 先完成草案，再集中修复

默认硬件执行策略为 `draft-then-repair.v1`。17 步先完成可执行的工程草案，把检查缺陷随检查点保存；最后调用前端选择的强模型进行集中工程修复，再以原始严格检查决定发布。没有配置升级模型时，最终修复沿用主模型。

## 草案与发布的区别

草案阶段不会把失败检查改成通过：`ok=false`、严重级别、受影响实体与原始证据全部保留。只对允许延后的问题取消即时停止，不进行步骤内部的 AHE 设计修复循环。最终重检从原校验器获取结果，不读取草案延后标记作为通过依据。

| 失败 | 草案处理 |
|---|---|
| 有效工程上的 ERC、布局、未连接、DRC、丝印与一般发布缺陷 | 记录，继续；最终修复 |
| 唯一缺陷是独立封装资料尚未核验，且已确认真实本地 KiCad 绑定 | 允许待核验草案；最终重新读取资料 |
| 真实资产缺失、封装不兼容、准备清单损坏或其它执行阻断 | 保留检查点并停止 |
| 生成器异常、模型/API/路由工具不能执行或没有有效后续输入 | 由原执行恢复机制处理；不冒充已完成步骤 |

“先完成 17 步”是尽力生成目标，不能保证工具不可用时仍完成。制造阶段产生的草案文件不构成正式发布，最终修复与严格复核未通过时，报告会保留明确的发布阻碍。

## 最终修复

`src/ratsnestpro/repair/draft.py` 负责草案调度规则和最终协调；它复用既有工程步骤，不另建一套原理图或布局生成器。

1. 保存完整草案的缺陷清单、阶段和最终修复次数；17 步完成后进入 `final_repair`。
2. 最终工程步骤与 AHE 使用已选强模型；独立资料缺失先尝试用已有文档重新核验。缓存的失败视觉解析允许一次重新观察，不无限重试。
3. 对现有 Artifact 重新执行严格检查，从最早未通过的所有者开始。原理图／网表修改使用现有步骤与 typed CAD 工具；物理 PCB 修改使用隔离强模型执行器。
4. 保留有效祖先及未变化的工程候选。选型仅补充资料、没有改变器件身份及功能时，保留已有电路与 PCB。工程契约或真实 CAD 文件变化时，失效其后续依赖并重建；这是保守的顺序依赖，尚不是按每条网络精细失效的 DAG。
5. 候选修改使用现有工程快照保护；失败恢复完整草案，保留最终失败证据和已消耗的修复次数。成功修改后重新生成制造文件，不复用旧草案 Gerber／钻孔／BOM。
6. 最终严格检查通过后，原有独立 Reviewer、发布身份和 Manifest 链路继续决定正式交付。

每次任务默认至多 3 轮最终协调；每轮内部沿用已有有界修复额度。最终 PCB 执行器在路由修复入口的第一次失败即可接手，无需再次等待普通修复积累两次失败。全局额度、真实物理检查及用户已确认约束保持有效。

## 检查点与可观测性

`pipeline_state.json` 保存 `draft_execution`，包含 `policy`、`phase`、逐步骤 `issues`、`repair_passes` 和实际修复模型。恢复时重新检查 Artifact，但允许恢复同样可延后的草案缺陷，避免下一次 Temporal Activity 又退回第 3 步。

事件包含 `draft.issues_deferred`、`draft.final_repair_started`、`draft.dependencies_invalidated`、`draft.final_repair_verified` 和 `draft.final_repair_needs_attention`。中间回执始终 `release_ready=false`；最终回执增加 `execution_phase` 和 `draft_execution`。

Temporal 仍按原活动与检查点调度，集中修复在最后的制造 Activity 内执行。进程中断可使用已有候选和检查点恢复。此版本没有把 17 步重写成新的 Temporal Workflow，也没有赋予模型修改发布校验器的权限。

## 配置和验证

运行时默认启用。需要回到逐步骤修复时设置 `RATSNESTPRO_DRAFT_THEN_REPAIR=false`；该设置用于部署配置，不由模型修改。前端选择升级模型和推理强度后启动新任务即可使用最终强模型修复。

定向测试覆盖：草案保留错误且不修复、无法继续的输入仍停止、只允许真实兼容资产延后独立资料核验、草案恢复不丢前缀、真实 CAD 原地修改使下游失效、最终修复保留祖先并重建制造、最终次数耗尽不能误放行。测试不等于新策略已完成该复杂板卡的自主 E2E；实际成功率仍需真实运行采集。
